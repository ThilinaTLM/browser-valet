# Browser automation

How commands are parsed and run, and how CDP is used to read and drive pages. Code:
`extension/src/background/` (`dispatch.ts`, `command.ts`, `cdp.ts`, `input.ts`, `snapshot.ts`,
`dom.ts`, `commands/*.ts`). The agent-facing command reference is in `cli/skills/core/`.

## Rules

- **Default:** commands mirror [agent-browser](https://github.com/vercel-labs/agent-browser) names, flags and snapshot format (principle 5 in [README.md](README.md)). When adding a command, copy agent-browser's syntax if it has one. *Why:* agents already know that vocabulary, and the skill relies on it.
- **Default:** a new command is a `Command` entry in `commands/*.ts`, registered in `COMMANDS` (`dispatch.ts`). Help and `--json` output come from that table. The CLI needs no change.
- **MUST** prime before any trusted input on a possibly hidden tab (use the helpers in `input.ts`). *Why:* agent tabs open in the background. Chrome doesn't render hidden tabs and drops input aimed at them.
- **MUST** get the tab via `ctx.tab()` (see [security.md](security.md)).
- **Default:** CDP calls that may hang on hidden or dialog-blocked pages are raced against a short timeout (prime 500 ms, input events 300 ms) or against `raceDialog`.
- **Default:** behaviour or output changes update `cli/skills/core/` in the same change.
- **MUST** put side information on stderr as `Result.warning` (`⚠ …`) and keep stdout to the result. *Why:* agents parse stdout; a notice mixed into it breaks `--json` and pipes.
- **MUST** give a `UserError` a `code` when the table in [Output conventions](#output-conventions) has one that fits. *Why:* agents branch on `--json` `code` instead of matching message text.
- **Default:** a new command's JSON `data` copies agent-browser's field names where the data is the same (`{ clicked }`, `{ value }`, `origin` on page reads); keep bctl-only fields next to them.

## Design

- **Dispatch:** `execute` parses argv (`parseArgs`: `--k=v`, combined short booleans, `--`, negative numbers) and finds the command. It runs the command under an `AbortController` and formats `{exitCode, stdout, stderr, files}` (text or `--json` `{success, data, error}`). `cancel` aborts waits, consent and dialogs, but not a CDP call already in flight.
- **CDP:** `chrome.debugger` protocol 1.3 is attached lazily per tab, with `Page` and `Runtime` enabled. Console messages and exceptions are buffered per tab in memory. `Network.enable` is sent lazily by the first `network` command on a tab; the request ring buffer lives in `network.ts` (see [security.md](security.md) for its redaction rules). `alert` and `beforeunload` dialogs are auto-accepted. `confirm` and `prompt` end the command early so that the agent can use `dialog accept|dismiss`.
- **Pointer commands:** `mouse move|down|up|wheel` send `Input.dispatchMouseEvent` after `prime`. The pointer position and held buttons are kept per tab in memory (`commands/extra.ts`), so moves while a button is held report `buttons` and `down`/`up` act at the last position (0,0 before any move). `move --duration ms --steps n` interpolates; steps default to one per 16 ms of duration. Chrome never processes wheel input for hidden tabs, so on a hidden tab `mouse wheel` scrolls the element under the pointer by script (no `wheel` event reaches the page). Hidden tabs also coalesce moves to about one per frame.
- **Highlight:** `highlight <t>` draws `Overlay.highlightNode` (enables `DOM` and `Overlay`) and hides it after 3 s with `Overlay.hideHighlight`, or when the tab is highlighted again. A service-worker restart in between leaves it until the page reloads.
- **Selectors:** targets are `@ref`, CSS or XPath. `dom.ts` treats a target starting with `/` or `(` as XPath (first match via `document.evaluate`); `get count` counts all matches. `wait`, `click` and the rest go through `resolve`, so they accept XPath too.
- **`get styles`:** prints `name: value` lines for a curated set (font, colour, background, display, visibility, opacity, position, size, margin, padding, border, z-index, cursor, pointer-events, overflow); `get styles <t> <prop…>` only those; `--all` every computed property, sorted (upstream prints all by default, ~450 lines).
- **`pushstate <url>`:** same-origin only. Uses `window.next.router.push` when present, otherwise `history.pushState` plus a `popstate` event. Prints the resolved URL.
- **`session list|info`:** read-only views of `state.sessions`/`state.tabs`: current tab (only if shared with the agent), owned tabs and last activity from the activity log. `info` shows tab, label, title, URL and `Frame:` (`main`, or the name set by `frame`). Unlike upstream, `--json` `sessions` are objects, not names.
- **Output conventions:** `execute` (`dispatch.ts`) is the only place that formats results and errors.
  - *Warnings:* `Result.warning` (string or list) is written to `stderr` as `⚠ <text>` lines, for text and `--json` alike; `stdout` carries only the result. Used for: a confirm/prompt dialog that opened during an action (`raceDialog`; JSON `data.dialog` also has it), a truncated full-page screenshot, the `network` "recording started" hint and the `tab` "not shared" hint.
  - *Errors:* text mode prints `✗ <message>` on stderr. `--json` prints `{ success: false, data: null, error, code? }` on stdout (exit 1); `code` is omitted when the failure has no stable code. Unknown commands also carry `type: "unknown_command"`, as agent-browser does. `UserError(message, code?)` lives in `errors.ts`.
  - *Usage:* a `bad_args` error whose message has no `Usage:` line gets `Usage: bctl <usage>` appended from the `Command` table.
  - *Help:* `Command.details` (a behaviour paragraph) and `Command.examples` are rendered by `<cmd> --help`; top-level help starts with the "Start here (for AI agents): `bctl skills get core`" line.
  - *`wait`:* `--url` prints the URL that matched (`{ url }`), `--text` prints the text (`{ text }`), `wait <ms>` has `{ ms, waited }`; element, `--fn` and `--load` waits print `✓ Done`.
  - *JSON fields:* actions echo their target (`{ clicked: "@e3" }`, `filled`, `typed`, `pressed`, `hovered`, `focused`, `checked`, `unchecked`, `scrolled`, `dragged`+`source`+`target`, `keydown`/`keyup`); `get`, `eval`, `is` and `snapshot` add `origin` (the tab URL); `get attr`/`value` use `{ value }`, `get count` `{ count, selector }`, `get box` the box fields; `console` is `{ messages: [{ type, text, args }] }` and `errors` `{ errors: [{ text, line, column, url }] }` (`args` are CDP RemoteObjects); `dialog status` has `hasDialog` and `open`; `tab` list is `{ tabs: [{ tabId, label, title, url, active, type, controlled, pending, current }] }` (`controlled` and `pending` are bctl-only).
  - *Error codes (`--json` `code`):*

    | code | when |
    |---|---|
    | `unknown_command`, `bad_args` | parsing / usage |
    | `unknown_ref`, `stale_ref`, `not_found`, `not_visible`, `disabled`, `covered` | targeting |
    | `timeout` | waits and the user not answering a consent prompt |
    | `dialog_open` | a confirm/prompt dialog blocks the tab |
    | `no_tab`, `tab_gone`, `not_shared`, `denied`, `revoked` | tabs and consent |
    | `not_connected`, `not_paired` | extension/proxy unreachable, CLI not paired (produced by the CLI and proxy, see [protocol.md](protocol.md)) |

    Errors that come straight from the page or Chrome (a JS exception in `eval`, a CDP failure, "Element is not editable") have no code.
- **Navigation:** `Page.navigate` can swap renderer processes and detach the debugger. In that case navigation retries once, then falls back to the tabs API. Discarded tabs are reloaded when selected.
- **Snapshot and refs:** `Accessibility.getFullAXTree` is rendered as an agent-browser-style tree. Refs `@eN` go to interactive roles and to named headings, images, cells and dialogs. Refs are **stable and monotonic** (as in agent-browser): the tab keeps a `backendNodeId → ref` map (`state.refs[tabId]`, pure logic in `ref-table.ts`), so `snapshot`, `snapshot -i` and later snapshots give the same element the same ref, and new nodes take `e<nextRef>` from a counter kept per session (`state.sessions[s].nextRef`, raised above any ref already in the tab). A cross-document navigation of the main frame (link, reload, `open`) clears the tab's map but **keeps the counter**, so an old `@e7` fails with `Unknown ref: e7` instead of hitting a different element. The document is identified by the main frame's `loaderId` (`state.refDocs`, checked on `Page.frameNavigated` and again by `syncDocument` before every snapshot and ref resolution, which covers missed events and worker restarts); same-document navigation (`pushState`, hash) keeps refs. A full, unscoped snapshot drops refs whose node left the accessibility tree (`removedRefs`); scoped or depth-limited snapshots drop nothing. `resolveRef` falls back to a unique role+name match when a backend node id has gone stale, but only for refs of the current document. Iframes are inlined, same-process and out-of-process alike (see Frames below). A ref inside an out-of-process iframe is keyed by `(frameId, backendNodeId)`, because backend node ids are per renderer process; `RefInfo` carries `sessionId` and `frameId` for those.
- **Frames (out-of-process iframes):** `cdp.attach` sends `Target.setAutoAttach {autoAttach, flatten, waitForDebuggerOnStart: false, filter: iframe}` and keeps the reported iframe targets as `state.childSessions[tabId]` (`ChildSession`: `sessionId`, `targetId` = the iframe's frame id, `parent` session for nested out-of-process iframes, `url`). Auto-attach is enabled again inside each child, so a cross-site iframe in a cross-site iframe is reached too. Anything that is not `type: iframe` is detached at once. `cdp.send(tabId, method, params, sessionId)` addresses a child with `chrome.debugger` `{tabId, sessionId}` (needs Chrome 125+, our floor is 127; spiked on Chrome for Testing 152). Events of child sessions are not enabled and never reach the tab's console, dialog or navigation handling. A child session dies with the tab's debugger session (revoke, detach, navigation that swaps the renderer) or when the iframe navigates; `Session with given id not found` is reported as "The iframe is gone…" (code `stale_ref`; never an attach conflict, which only concerns the tab-level `attach`) and the session is forgotten. Rules:
  - **Snapshot:** for an `Iframe` AX node, `DOM.describeNode` gives the hosted frame id. A child session with that target id has its own full AX tree (`Accessibility.getFullAXTree` on the session, no `frameId`); otherwise the tree is read from the parent's session with `frameId` (same process). A just-created iframe is awaited up to 0.8 s. An iframe that exists but cannot be read keeps its refs in a full snapshot (they are not reported in `removedRefs`). `Iframe` nodes stay in `-i` output because `frame @ref` needs them. Clickable detection (`cursor:pointer`) covers only the main frame.
  - **Resolving:** a ref with `frameId` is resolved in the session that currently serves that frame (looked up by frame id, not by the stored `sessionId`, which is only a hint), so a ref survives the iframe's session being re-created. `Handle.sessionId` makes `call`, `scrollIntoViewIfNeeded`, `setFileInputFiles` and `highlight` run in that session.
  - **Input goes to the child session, not the tab.** `clickPoint` returns coordinates relative to the iframe and the session; `click`, `dblclick`, `hover` send `Input.dispatchMouseEvent` there. *Why:* the plan was to add the iframe's content-box offset (and each parent's) and dispatch on the tab, but on a hidden tab Chrome has no hit-test data for an out-of-process iframe and routes the click to the parent page (observed: the parent got `mousedown`, the iframe nothing, even after `prime`). Dispatching to the child's own widget needs no offset and works hidden or visible. Nested same-process frames report coordinates relative to their session's root, so they work the same way. Keyboard input (`type`, `press`, `fill`'s `insertText`) goes to the tab and reaches the focused frame. `drag` inside an out-of-process iframe is refused (drag interception events are not collected for child sessions).
  - **`screenshot --annotate`:** refs inside an out-of-process iframe are boxed too: the node is measured in its child session, shifted by the iframe's content box (`frameBox`, summed over nested iframes) and clipped to it. A ref whose iframe session is unknown is skipped.
  - **`frame <selector|@ref|name|url|main>`:** sets `state.frames[tabId] = {frameId, name}` (per tab, like refs, not per session). The target is an `<iframe>`/`<frame>` element (a ref, CSS or XPath, resolved from the main frame) or else a frame matched by name, then URL (exact, then substring) over `Page.getFrameTree` of the tab and of every child session. `main` clears it. A failed `frame` leaves the previous scope. While set, `snapshot` (starts at that frame's document and prunes nothing), CSS/XPath targets (`resolve`), `get text|html|count|…`, `eval` and `wait --fn` run in that frame; `get title|url` and `wait --text|--url|--load` stay on the tab; refs always use their own frame. An out-of-process frame is evaluated through its session; a same-process frame through its element's `contentWindow.eval` (same-origin only, otherwise "cannot be scripted from here"). `clearRefs` (any main-frame cross-document navigation, caught by `Page.frameNavigated` or by `syncDocument`) clears the scope, so navigation resets it. `find` locators ignore the scope. Errors: `not_found` (no such frame or element), `bad_args` (the element is not an iframe). Upstream differs: its `frame` only scopes `snapshot`/`get`/selectors, while `eval`, `get title` and `wait --fn` still run in the main frame (observed on 0.41.2), and it only takes a selector or ref.
  - **Service-worker restart:** `state.childSessions` is persisted, so the next command reuses the sessions of the surviving debugger attachment. If a frame is unknown after a restart (`resumed` attachment, no session in `state`), `sessionForFrame` re-attaches the debugger once per attach epoch, because Chrome reports child targets only to a new attachment (`setAutoAttach` again, even after turning it off, does not repeat them; `Target.attachToTarget` and `Target.getTargets` are "Not allowed" for tab sessions). This briefly drops the debugger session, and with it emulation overrides and the network buffer. A fresh attach and a self-update handoff discard `childSessions` (the reload ended every attachment); `frames` survives the handoff.
- **`snapshot --delta` / `--full`:** `inspection.ts` keeps an in-memory baseline per `(tabId, option set)` (`snapshot-diff.ts`; not persisted, because of the session-storage quota, so the first `--delta` after a service-worker restart returns the tree). The option set is interactive/compact/depth/scope/urls. Every `--delta`/`--full` call takes the next revision of the tab (shared by all option sets) and replaces the baseline. `--delta` returns the full tree when there is no baseline, the tab URL (hash included) or main-frame document changed, or the delta JSON would not be shorter than the tree (agent-browser's observed behaviour; stricter than the 50 % rule first proposed). Otherwise `unchanged (revision N)`, or pretty JSON `{ baseRevision, changes, kind: "delta", revision, treeChange: { deleteCount, lines, startLine } }` even without `--json`. `treeChange` is the one contiguous splice (common prefix and suffix kept, `startLine` 0-based); `changes` lists `add` (`node: {name, role}`), `remove` and `replace` (`field: name|role`, `value`) per ref, ordered by ref number. `--full` returns the tree and resets the baseline. A plain `snapshot` neither reads nor changes baselines. `--json` data is `{ origin, snapshot }` where `snapshot` is `{kind: "unchanged"|"delta", …}` or `{kind: "full", refs, revision, tree}`.
- **Clickable non-semantic elements:** one `Runtime.evaluate` per snapshot (`clickable.ts`) finds elements without an interactive role that are `cursor:pointer` (only when the parent's cursor is not already pointer, since the cursor is inherited), have `onclick` or `tabindex >= 0`. It skips natively interactive tags, hidden and zero-size elements, and stops at 500. Each candidate is matched to its AX node by backend id (`Runtime.getProperties` + `DOM.describeNode`); the node gets a ref and the suffix `clickable [cursor:pointer, onclick]` (`focusable [tabindex]` when `tabindex` is the only reason), as in agent-browser 0.41.2 (checked on a fixture: it does **not** skip candidates inside an element that already has a ref, only inherited pointers). In `-i` mode an unnamed candidate takes its text content (whitespace collapsed, ≤150 chars) as its name; upstream keeps raw whitespace. Listeners added with `addEventListener` and elements inside iframes are not detected. Cost: every clickable wrapper adds a line with its lifted text, so a list where each row is a clickable `div` roughly quintuples `-i` size (a synthetic 150-row inbox: 8.7 KB → 41 KB); `-s` scoping keeps it down. `snapshot --json` data is `{ origin, title, refs, removedRefs, snapshot }`.
- **`read [url]`:** page text as markdown. With a URL it first runs `open <url>` (so it never navigates a shared tab), then evaluates `dist/read-extractor.js` in the page (loaded once from the extension package, so it stays out of the service-worker bundle; ~46 KB minified with Mozilla Readability and Turndown). The extractor takes the largest `main`/`[role=main]`/`article`; without one, Readability picks the content, else the body. `script`, `style`, `nav`, `aside` and hidden elements are dropped. Links keep their text only, tables become GFM tables. `--outline`, `--filter` and `--max-output` run in the service worker on the markdown (`read-format.ts`) and mirror agent-browser 0.41.2: `# Outline` / `Source: <url>` / nested `- heading` list; `--filter` returns each section (heading + subsections) whose heading or own text contains the text, or `No matching page sections`; truncation appends `[truncated: showing N of M chars. Use --max-output to adjust]`. No HTTP fetch mode (`--llms`, `--require-md`) by design: the CLI stays thin and a service-worker fetch would send cookies without a visible tab.
- **Input:** `prime` checks `document.visibilityState`. If the page is hidden, a 1×1 `Page.captureScreenshot` forces a frame, and then `Input.dispatch*` delivers trusted events without focusing the tab. Held modifier keys are module-global.
- **`pdf <path> [--landscape] [--background]`:** `Page.printToPDF`, returned in `res.files`. Read-only, so allowed on agent and shared tabs. Spike result: `Page.printToPDF` works through `chrome.debugger` in headed Chrome for Testing (verified under Xvfb with `E2E_HEADFUL=1`), including on background tabs; a failure is reported as "Chrome could not print this page to PDF".
- **`set viewport <w> <h> [scale]` / `set media [dark|light] [reduced-motion]` (+ `reset`):** `Emulation.setDeviceMetricsOverride` / `setEmulatedMedia`, **agent tabs only**; a shared tab is refused with an error because the user would see their own page change. The override lives in the tab's debugger session: it persists across navigations while attached and ends on `close`, revoke or detach (the extension tracks no state). The user sees the emulated viewport if they switch to an agent tab. `set device/geo/offline/headers/credentials` are refused: they change what servers see in a logged-in account.
- **`screenshot --annotate`:** takes a fresh snapshot (new refs only for new elements, as always), reads each ref's box with `DOM.getContentQuads` and draws a red outline plus a red number tag in an `OffscreenCanvas` over the captured image (`annotate.ts`). Nothing is injected into the page. The tag number equals the ref number. Output is the save line followed by `   [N] @eN role "name"` lines; JSON adds `annotations: [{ref, number, role, name, box}]` (CSS px; viewport-relative, or page-relative with `--full`). Elements outside the viewport are skipped unless `--full`.
- **`screenshot --if-changed` / `--threshold <0-1>`:** the capture is downscaled to at most 640 px wide and compared with the last one for the same (tab, scope: viewport/full × annotated or not), kept in memory only (`capture-compare.ts`, dropped when the tab is forgotten). A pixel counts as changed if a channel differs by more than 8. The first capture is always changed (ratio 1, revision 1). Unchanged (`ratio <= threshold`) prints `✓ Screenshot unchanged (revision N, 0.0000% pixels changed)` and writes no file; the reference image is then kept so slow drift accumulates. JSON: `changed`, `pixelChangeRatio` (fraction), `revision`, `threshold`, plus `path` when changed. `--threshold` implies `--if-changed`; with `--annotate` the comparison uses the plain capture and annotations are only computed for a changed capture. The revision counts per scope. A capture on a hidden tab that never answers is retried (`captureScreenshot`).
- **Full-page screenshots:** the page size comes from `Page.getLayoutMetrics`. Captures in 8000 px slices are stitched in an `OffscreenCanvas`, capped at 32000 device px (`truncated` flag).

- **Attach conflicts:** `cdp.attach` treats "already attached" as possibly ours (a previous worker's attachment) and probes with a cheap `Runtime.evaluate`. If the probe fails, another debugger owns the tab and the command fails with "Another debugger is attached to this tab (DevTools or another extension). Close DevTools on this tab…". Chrome's wording is identical for both cases, so only the probe tells them apart. Observed in Chrome for Testing 152 (`chrome.debugger` from the extension worker): `attach` on a tab the extension already holds → `Another debugger is already attached to the tab with id: N.`; `sendCommand` or `detach` on a tab the extension does not hold → `Debugger is not attached to the tab with id: N.` (a probe on a foreign attachment fails this way). A second CDP client (such as DevTools or puppeteer) does not cause either error: Chrome allows several clients on one tab. The foreign-debugger case therefore needs another extension holding `chrome.debugger`, and is covered by a unit test, not an E2E test.
- **`batch`** (`commands/batch.ts`): `bctl batch "cmd" "cmd" …`, or one command per line with `--stdin`; `--bail` stops at the first failure; `--omit-command` (with `--json`) swaps each `command` for an `index`. The dispatcher hands the call to `runBatch`, which splits each item with a small tokenizer (single and double quotes, backslash escapes, **no expansion**) and runs it through `execute` itself, so parsing, `Ctx`, `raceDialog`, consent, errors, warnings and the activity log are exactly those of a single call. Rules:
  - **MUST** log per item through `execute` (`describe`/`logArgs` redaction) and never log the raw batch line (`batch` itself has `log: () => []` and writes no entry). *Why:* the line carries every item's free text and secrets.
  - **MUST** reject inside an item: `--session` (set it on the batch; it and `--timeout`/`--json` apply to every item, `--timeout` per item, not for the whole batch), `--stdin` (stdin is the batch), and `batch`. `eval -b` works. A rejected or malformed item (unterminated quote) is a failed item, not a failed batch.
  - **MUST** share one `AbortSignal`: when the CLI disconnects the current item aborts and the rest are skipped. A confirm/prompt dialog (item `data.dialog`) ends the batch like it ends a single command; later items would only fail with `dialog_open`.
  - Output (matches agent-browser 0.41.2): text is each item's stdout joined by `\n` (so a blank line between items; a failed item contributes nothing), warnings and `✗ …` errors go to stderr in order; exit 1 if any item failed, with or without `--bail`. `--json` is a **top-level array** `[{command, success, result, error}]` (not `{success, data}`): `result` is the `data` the item returns alone, `error` the message, no `code`. `res.files` of all items are merged.
  - Not adopted from upstream: its stdin is a JSON array of argv arrays; ours is one command per line. No `[n]` prefixes in text mode.

## Gotchas

- Attaching shows Chrome's debugging bar. Closing it revokes the tab (see [security.md](security.md)).
- Hidden tabs throttle timers and stop `requestAnimationFrame`. Waits based on page JS may be slow in agent tabs.
- `raceDialog` returns while the command keeps running in the background. Its later side effects (grants, log entries) still happen.
- Dialogs, console messages and exceptions of an out-of-process iframe are not captured (its `Page`/`Runtime` domains are not enabled), so an `alert` inside one is not auto-accepted.
- Pointer state (`mouse`) is per tab and, like held modifier keys, lost on a service-worker restart.
- Held modifier keys (`keydown`) are shared across tabs and sessions and are lost on a service-worker restart.
- `tab` (list) assigns `tN` ids to every tab it lists, shared or not. This is intended: the agent needs an id to ask for an unshared tab.
- The supported floor is Chrome 127 (`minimum_chrome_version`). `build.mjs` targets the same version; change both together.
