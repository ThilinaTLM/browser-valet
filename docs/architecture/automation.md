# Browser automation

How commands are parsed and run, and how CDP is used to read and drive pages. Code:
`extension/src/background/` (`dispatch.ts`, `command.ts`, `cdp.ts`, `input.ts`, `snapshot.ts`,
`dom.ts`, `commands/*.ts`). The agent-facing command reference is in `cli/skills/core/`.

## Rules

- **Default:** commands mirror [agent-browser](https://github.com/vercel-labs/agent-browser) names, flags and snapshot format (principle 5 in [README.md](README.md)). When adding a command, copy agent-browser's syntax if it has one. *Why:* agents already know that vocabulary, and the skill relies on it.
- **Default:** where agent-browser's docs and its binary disagree (its skill shows a `Page:`/`URL:` snapshot header and `@e1 [tag]` lines that 0.41.2 does not print), match the binary. Run the upstream binary against local fixtures before changing output to follow a new upstream version.
- **Default:** a new command is a `Command` entry in `commands/*.ts`, registered in `COMMANDS` (`dispatch.ts`). Help and `--json` output come from that table. The CLI needs no change.
- **MUST** prime before any trusted input on a possibly hidden tab (use the helpers in `input.ts`). *Why:* agent tabs open in the background. Chrome doesn't render hidden tabs and drops input aimed at them.
- **MUST** get the tab via `ctx.tab()` (see [security.md](security.md)).
- **MUST NOT** focus or raise a tab or window, except `tab show` (explicit hand-off; principle 7). It needs the tab to be controlled (agent or shared; `not_shared` otherwise, never prompts), does not change grants or the session's current tab, and falls back to `drawAttention` if Chrome refuses focus. The popup's Agent tabs rows send the same `focus` message. No tab groups (principle 6).
- **Default:** CDP calls that may hang on hidden or dialog-blocked pages are raced against a short timeout (prime 500 ms, input events 300 ms, touch acks an 8 s budget per gesture) or against `raceDialog`.
- **Default:** behaviour or output changes update `cli/skills/core/` in the same change.
- **MUST** put side information on stderr as `Result.warning` (`⚠ …`) and keep stdout to the result. *Why:* agents parse stdout; a notice mixed into it breaks `--json` and pipes.
- **MUST** give a `UserError` a `code` when the table in [Output conventions](#output-conventions) has one that fits. *Why:* agents branch on `--json` `code` instead of matching message text.
- **Default:** a new command's JSON `data` copies agent-browser's field names where the data is the same (`{ clicked }`, `{ value }`, `origin` on page reads); keep bvl-only fields next to them.

## Design

- **Dispatch:** `execute` parses argv (`parseArgs`: `--k=v`, combined short booleans, `--`, negative numbers) and finds the command. It runs the command under an `AbortController` and formats `{exitCode, stdout, stderr, files}` (text or `--json` `{success, data, error}`). `cancel` aborts waits, consent and dialogs, but not a CDP call already in flight.
- **CDP:** `chrome.debugger` protocol 1.3 is attached lazily per tab, with `Page` and `Runtime` enabled. Console messages and exceptions are buffered per tab in memory. `Network.enable` is sent lazily by the first `network` command on a tab; the request ring buffer lives in `network.ts` (see [security.md](security.md) for its redaction rules). `alert` and `beforeunload` dialogs are auto-accepted. `confirm` and `prompt` end the command early so that the agent can use `dialog accept|dismiss`.
- **Pointer commands:** `mouse move|down|up|wheel` send `Input.dispatchMouseEvent` after `prime`. The pointer position and held buttons are kept per tab in memory (`pointer.ts`), so moves while a button is held report `buttons` and `down`/`up` act at the last position (0,0 before any move). `move --duration ms --steps n` interpolates linearly; steps default to one per 16 ms of duration, capped at 240. `--steps` must be an integer 1–240 and `--duration` 0 or more, else `bad_args` (earlier versions clamped `--steps` at 500 and treated a negative duration as 0). Chrome never processes wheel input for hidden tabs, so on a hidden tab `mouse wheel` scrolls the element under the pointer by script (no `wheel` event reaches the page). Hidden tabs also coalesce moves to about one per frame.
- **Human pointer paths (`--human`):** `click`, `dblclick`, `hover`, `drag` and `mouse move` accept `--human`; `mouse move` also `--seed n`. Upstream has `--human` only on `click`, `drag` and `mouse move`; `dblclick` and `hover` are bvl additions. `human-path.ts` (pure) builds the path: a cubic Bézier with two control points offset perpendicular to the line, smootherstep ease-in-out spacing, and for moves over 400 px a 3–15 px overshoot that settles back, ending exactly on the target. Same seed, start and target give the same points; without `--seed` it is random (`mouse move --json` reports the `seed` used). Duration defaults to 250–700 ms by distance (`--duration` overrides) with one event per ~16 ms (8–240; `--steps` overrides). The start is the tab's last pointer position (`pointer.ts`, shared with `mouse`; every click, hover, drag and `mouse move` updates it, in the coordinates of the session that received it, so inside a child-session iframe the start is only meaningful for the same frame). `click`/`dblclick`/`hover` resolve `clickPoint` first, dispatch the path as `mouseMoved`, and, if the path took over 200 ms measured (always, with the default 250 ms minimum), re-run `clickPoint` and move straight to the point if it shifted, then press without a second hover move; `drag --human` presses on the source and curves to the target with the button held (no approach path to the source). `mouse move` and the click/hover/drag approaches share one `travel` helper (`input.ts`): the pointer's held buttons are reported on every move, points are clamped to ≥ 0. On hidden tabs all moves but the last are sent without waiting for acknowledgement (a 240-step path would otherwise cost up to 72 s), and the renderer coalesces them to about one per frame, so fewer arrive than were sent. The last move is awaited so a native HTML5 drag has been intercepted before `drag` drops. Not a bot-detection bypass.
- **`tap <t>` / `swipe <dir> [px] [--selector t] [--duration ms]`:** touch input with `Input.dispatchTouchEvent` after `prime`. `tap` uses `clickPoint` (same targeting and actionability as `click`; for a node in an out-of-process iframe the touches go to its child session) and sends `touchStart`/`touchEnd`. Chrome then synthesizes the compatibility mouse events itself (`mouseover`, `mousedown`, `click`), so links and buttons activate like a user's tap; E2E-verified, and `tap` appears in the navigation report. Inside an out-of-process iframe the touches go straight to the child session and the page's touch listeners fire, but whether Chrome also synthesizes the click there is not reliable (it differed between a local run and CI), so use `click` for plain `onclick` buttons in iframes. JSON `{ tapped }` (upstream: alias of `click`). `swipe` starts at the viewport centre (or the `--selector` element), sends 10 `touchMove`s over `--duration` (default 300 ms; Chrome coalesces some per frame) and `touchEnd`. Direction is where content moves (`swipe up` scrolls down, as upstream). Without `--selector` the end point is clamped to the viewport; the JSON `distance` is the real distance and a warning says it was shortened. Without `--selector` the touches are sent to the tab, not to a cross-origin iframe under the centre; use `--selector` on an element inside the iframe. `--selector` and `--duration` are bvl additions (upstream `swipe` is iOS-only, flagless). Both work on shared tabs: they only deliver input, like `click`, and need no emulation.
  - **Acks on hidden tabs (`touch()` in `input.ts`):** unlike mouse events, a touch event is acknowledged by the page only after it produces a frame, so on a hidden tab each event is sent without waiting, then 1×1 `Page.captureScreenshot` calls force frames (each round waits ≤ 50 + 300 ms) until the ack arrives. A gesture shares one 8 s budget (`ACK_BUDGET_MS`): after it, events are still sent in order but not waited for, so a 12-event swipe stays far below the 25 s command timeout (worst case ≈ budget + ~1.2 s + `--duration`). Rejections are swallowed (the next CDP call reports a closed tab).
- **Highlight:** `highlight <t>` draws `Overlay.highlightNode` (enables `DOM` and `Overlay`) and hides it after 3 s with `Overlay.hideHighlight`, or when the tab is highlighted again. A service-worker restart in between leaves it until the page reloads.
- **Timeouts:** `--timeout` defaults to 25 s (`DEFAULT_TIMEOUT`, `dispatch.ts`). CSS/XPath targets are re-resolved every 100 ms for up to `min(--timeout, 5000)` ms before failing (`resolveWait`, `dom.ts`); refs and malformed selectors fail at once.
- **Selectors:** targets are `@ref`, CSS or XPath. `dom.ts` treats a target starting with `/` or `(` as XPath (first match via `document.evaluate`); `get count` counts all matches. `wait`, `click` and the rest go through `resolve`, so they accept XPath too. Playwright-style locators (`text=…`, `role=…`, `:has-text(…)`) are not supported; their `Invalid selector` error names the matching `find` command instead.
- **`eval` and `wait --fn` (`evaluateScoped`):** REPL mode (top-level `await`) by reference, then the value is fetched with `returnByValue`; a result that is a promise is first settled with `Runtime.awaitPromise`. *Why:* REPL mode awaits only its own completion, so `fetch(u).then(r => r.status)` came back as an unresolved promise and printed `{}`. An already rejected promise is reported by Chrome as an uncaught error before it is awaited; the `errors` buffer drops an entry again on `Runtime.exceptionRevoked`, as DevTools does.
- **`get styles`:** prints `name: value` lines for a curated set (font, colour, background, display, visibility, opacity, position, size, margin, padding, border, z-index, cursor, pointer-events, overflow); `get styles <t> <prop…>` only those; `--all` every computed property, sorted (upstream prints all by default, ~450 lines).
- **`pushstate <url>`:** same-origin only. Uses `window.next.router.push` when present, otherwise `history.pushState` plus a `popstate` event. Prints the resolved URL.
- **`session list|info`:** read-only views of `state.sessions`/`state.tabs`: current tab (only if shared with the agent), owned tabs and last activity from the activity log. `list` shows the current session and sessions that hold or own a tab. Reads use `peekSession`, which never creates an entry, and `execute` ends with `pruneSession`, which deletes an entry with no tab, no `nextRef` and no sites, so failed or read-only commands and `close` leave no session behind. `info` shows tab, label, title, URL and `Frame:` (`main`, or the name set by `frame`). Unlike upstream, `--json` `sessions` are objects, not names.
- **Guardrails:** policy, confirmation and the Fetch navigation guard are described in [security.md](security.md#guardrails); code in `guardrails.ts` (policy, pattern matching, output shaping, confirmation) and `navigation-guard.ts` (Fetch layer). `execute` calls them in this order: parse → `confirmCommand` (eval/upload) → `narrowFor` → `run` → refused-navigation check → `limitOutput` → `applyBoundaries`. A command that navigates calls `guardNavigation` (domain check, then new-site confirmation) before it acts.
- **Navigation:** `Page.navigate` can swap renderer processes and detach the debugger. In that case navigation retries once, then falls back to the tabs API. Discarded tabs are reloaded when selected. One deadline of `--timeout` covers the whole navigation: `Page.navigate` (which blocks until the response commits) is raced against it, then the load event. Nothing committed by the deadline → `Page.stopLoading` and `timeout` error; committed but not loaded → success with the warning `Page still loading after N ms; continuing (use wait --load or wait --text)` and JSON `loaded: false` (`loaded` is otherwise omitted). The HTTP status comes from `performance.getEntriesByType('navigation')[0].responseStatus` (probe ≤ 500 ms); when known it is JSON `status`, and ≥ 400 adds the warning `HTTP <status> from <url>`. Helpers: `nav-outcome.ts`. Applies to `open`, `tab new <url>`, `click --new-tab`, `read <url>`, `reload`, `back`/`forward`.
- **`fill`:** `time`, `date`, `datetime-local`, `month`, `week`, `color` and `range` inputs are set through the native value setter followed by bubbling `input` and `change` (text insertion does nothing on them). Other fields get `Input.insertText`. Afterwards the value of an input/textarea is read back (`fill-rules.ts`): empty for non-empty text → error `fill did not stick: value is ""`, with the expected format for date/time-like inputs and otherwise a hint that the page may have reset the field; different but non-empty → warning that the page changed it (never echoed for passwords; number, colour case and CRLF differences count as equal). Targeting an inner part of a date/time input fails with a message pointing at the outer `<input>`. A `role=combobox` target gets a warning (non-empty text only): many comboboxes (Oracle JET, for example) revert typed text on blur unless an option is picked from the popup, and checking that would need a blur, which changes page state.
- **Snapshot and refs:** `Accessibility.getFullAXTree` is rendered as an agent-browser-style tree. Refs `@eN` go to interactive roles and to named headings, images, cells and dialogs. Refs are **stable and monotonic** (as in agent-browser): the tab keeps a `backendNodeId → ref` map (`state.refs[tabId]`, pure logic in `ref-table.ts`), so `snapshot`, `snapshot -i` and later snapshots give the same element the same ref, and new nodes take `e<nextRef>` from a counter kept per session (`state.sessions[s].nextRef`, raised above any ref already in the tab). A cross-document navigation of the main frame (link, reload, `open`) clears the tab's map but **keeps the counter**, so an old `@e7` fails instead of hitting a different element. `clearRefs` records the highest `nextRef` of all sessions as `state.refDocStart[tabId]` (optional field, absent in older state). A missing ref below it is `stale_ref` "from a previous page"; a ref of the current document that is no longer in the table is `stale_ref` "no longer on the page"; a ref never issued (≥ every session's counter) is `unknown_ref`. Approximate when sessions share a tab. The document is identified by the main frame's `loaderId` (`state.refDocs`, checked on `Page.frameNavigated` and again by `syncDocument` before every snapshot and ref resolution, which covers missed events and worker restarts); same-document navigation (`pushState`, hash) keeps refs. A full, unscoped snapshot drops refs whose node left the accessibility tree (`removedRefs`); scoped or depth-limited snapshots drop nothing. `resolveRef` falls back to a unique role+name match when a backend node id has gone stale, but only for refs of the current document. Iframes are inlined, same-process and out-of-process alike (see Frames below). A ref inside an out-of-process iframe is keyed by `(frameId, backendNodeId)`, because backend node ids are per renderer process; `RefInfo` carries `sessionId` and `frameId` for those.
- **Frames (out-of-process iframes):** `cdp.attach` sends `Target.setAutoAttach {autoAttach, flatten, waitForDebuggerOnStart: false}` with a filter that admits only `iframe` targets (retried without the filter if Chrome rejects it) and keeps the reported iframe targets as `state.childSessions[tabId]` (`ChildSession`: `sessionId`, `targetId` = the iframe's frame id, `parent` session for nested out-of-process iframes, `url`). Auto-attach is enabled again inside each child, so a cross-site iframe in a cross-site iframe is reached too. Anything that is not `type: iframe` is detached at once. `cdp.send(tabId, method, params, sessionId)` addresses a child with `chrome.debugger` `{tabId, sessionId}` (needs Chrome 125+, our floor is 127; spiked on Chrome for Testing 152). Events of child sessions are not enabled and never reach the tab's console, dialog or navigation handling. A child session dies with the tab's debugger session (revoke, detach, navigation that swaps the renderer) or when the iframe navigates; `Session with given id not found` is reported as "The iframe is gone…" (code `stale_ref`; never an attach conflict, which only concerns the tab-level `attach`) and the session is forgotten. Rules:
  - **Snapshot:** for an `Iframe` AX node, `DOM.describeNode` gives the hosted frame id. A child session with that target id has its own full AX tree (`Accessibility.getFullAXTree` on the session, no `frameId`); otherwise the tree is read from the parent's session with `frameId` (same process). A just-created iframe is awaited up to 0.8 s. An iframe that exists but cannot be read keeps its refs in a full snapshot (they are not reported in `removedRefs`). `Iframe` nodes stay in `-i` output because `frame @ref` needs them. Clickable detection (`cursor:pointer`) covers only the main frame.
  - **Resolving:** a ref with `frameId` is resolved in the session that currently serves that frame (looked up by frame id, not by the stored `sessionId`, which is only a hint), so a ref survives the iframe's session being re-created. `Handle.sessionId` makes `call`, `scrollIntoViewIfNeeded`, `setFileInputFiles` and `highlight` run in that session.
  - **Input goes to the child session, not the tab.** `clickPoint` returns coordinates relative to the iframe and the session; `click`, `dblclick`, `hover` send `Input.dispatchMouseEvent` there. *Why:* the plan was to add the iframe's content-box offset (and each parent's) and dispatch on the tab, but on a hidden tab Chrome has no hit-test data for an out-of-process iframe and routes the click to the parent page (observed: the parent got `mousedown`, the iframe nothing, even after `prime`). Dispatching to the child's own widget needs no offset and works hidden or visible. Nested same-process frames report coordinates relative to their session's root, so they work the same way. Keyboard input (`type`, `press`, `fill`'s `insertText`) goes to the tab and reaches the focused frame. `drag` inside an out-of-process iframe is refused (drag interception events are not collected for child sessions).
  - **`screenshot --annotate`:** refs inside an out-of-process iframe are boxed too: the node is measured in its child session, shifted by the iframe's content box (`frameBox`, summed over nested iframes) and clipped to it. A ref whose iframe session is unknown is skipped.
  - **`frame <selector|@ref|name|url|main>`:** sets `state.frames[tabId] = {frameId, name}` (per tab, like refs, not per session). The target is an `<iframe>`/`<frame>` element (a ref, CSS or XPath, resolved from the main frame) or else a frame matched by name, then URL (exact, then substring) over `Page.getFrameTree` of the tab and of every child session. `main` clears it. A failed `frame` leaves the previous scope. While set, `snapshot` (starts at that frame's document and prunes nothing), CSS/XPath targets (`resolve`), `get text|html|count|…`, `eval` and `wait --fn` run in that frame; `get title|url` and `wait --url|--load` stay on the tab, and `wait --text` searches the whole page: the main frame and its same-origin frames from page script, then every child session (`pageHasText`; same-site cross-origin frames in the same process are not searched); refs always use their own frame. An out-of-process frame is evaluated through its session; a same-process frame with `Runtime.evaluate { contextId }` in its default (main-world) execution context, so page CSP without `unsafe-eval` (LinkedIn, GitHub) does not matter and page globals stay visible (`frames.ts` `evalInFrame`; never `contentWindow.eval`). Contexts are tracked per (tab, session, frameId) from `Runtime.executionContextCreated/Destroyed/Cleared`, listened to directly on `chrome.debugger` because `cdp.onEvent` only forwards the tab's own session. With no known context (service-worker restart, a child session whose `Runtime` is not enabled) `evalInFrame` does `Runtime.disable`+`enable` on that session to make Chrome re-emit them (on the tab's own session this may replay earlier console messages into the console buffer), and for DOM queries (`resolve`, `isolatedOk`) falls back to `Page.createIsolatedWorld`; otherwise it fails with `not_found`. A cross-origin frame in the same process cannot be scripted and says so. `resolve` reports `Invalid selector` only for a `SyntaxError`/`DOMException` from `querySelector`/`document.evaluate`; other exceptions show their real text. `get count` always prints a number or fails. `clearRefs` (any main-frame cross-document navigation, caught by `Page.frameNavigated` or by `syncDocument`) and a debugger detach clear the scope, so navigation resets it. `find` locators ignore the scope. Errors: `not_found` (no such frame or element), `bad_args` (the element is not an iframe). Upstream differs: its `frame` only scopes `snapshot`/`get`/selectors, while `eval`, `get title` and `wait --fn` still run in the main frame (observed on 0.41.2), and it only takes a selector or ref.
  - **Service-worker restart:** `state.childSessions` is persisted, so the next command reuses the sessions of the surviving debugger attachment. If a frame is unknown after a restart (`resumed` attachment, no session in `state`), `sessionForFrame` re-attaches the debugger once per attach epoch, because Chrome reports child targets only to a new attachment (`setAutoAttach` again, even after turning it off, does not repeat them; `Target.attachToTarget` and `Target.getTargets` are "Not allowed" for tab sessions). This briefly drops the debugger session, and with it emulation overrides and the network buffer. A fresh attach and a self-update handoff discard `childSessions` (the reload ended every attachment); `frames` survives the handoff.
- **`snapshot --delta` / `--full`:** `inspection.ts` keeps an in-memory baseline per `(tabId, option set)` (`snapshot-diff.ts`; not persisted, because of the session-storage quota, so the first `--delta` after a service-worker restart returns the tree). The option set is interactive/compact/depth/scope/urls (plus the `frame` scope when one is set, so a framed and an unframed snapshot no longer share a baseline). Every `--delta`/`--full` call takes the next revision of the tab (shared by all option sets) and replaces the baseline. `--delta` returns the full tree when there is no baseline, the tab URL (hash included) or main-frame document changed, or the delta JSON would not be shorter than the tree (agent-browser's observed behaviour; stricter than the 50 % rule first proposed). Otherwise `unchanged (revision N)`, or in text mode a compact diff (`formatDeltaText`): a header `delta (revision A → B, lines S-E)` (`line N` for one line, `insert at line N` for a pure insertion before baseline line N; 1-based baseline lines), then the removed baseline lines prefixed `- ` and the new lines prefixed `+ `. Inside the splice an LCS (`spliceHunks`, skipped above 2 M cells) separates real changes: several hunks print `delta (revision A → B, N changes)` and one `@ <where>` line per hunk, so equal lines between two edits are not repeated. The size rule compares this text with the tree. *Why:* agent-browser's pretty JSON listed each change twice (~2.5 KB for a 4-line change); `--json` keeps the structured form `{ baseRevision, changes, kind: "delta", revision, treeChange: { deleteCount, lines, startLine } }`. `treeChange` is the one contiguous splice (common prefix and suffix kept, `startLine` 0-based); `changes` lists `add` (`node: {name, role}`), `remove` and `replace` (`field: name|role`, `value`) per ref, ordered by ref number. `--full` returns the tree and resets the baseline. A plain `snapshot` neither reads nor changes these `--delta` baselines (it only records its text for `diff snapshot`, below). `--json` data is `{ origin, snapshot }` where `snapshot` is `{kind: "unchanged"|"delta", …}` or `{kind: "full", refs, revision, tree}`.
- **`diff snapshot [--stdin] [-s] [-c] [-d]` (`commands/diff.ts`):** takes a snapshot and prints a unified diff (`--- before` / `+++ after`, `@@ -a,b +c,d @@` hunks with 3 lines of context), a blank line, then `N additions, N removals, N unchanged`, as agent-browser 0.41.2 does. Identical trees print `✓ No changes detected`. `--json` data is `{ diff, additions, removals, unchanged, changed }`.
  - **Refs are ignored when comparing, kept when printing.** Refs keep counting up across reloads and navigation (`refs.ts`), so comparing raw lines would flag every ref line. Like upstream's `snapshot_comparison_text`, `stripRef` removes the `ref=eN` attribute from the `[a, b, ref=eN]` group (only the attribute group after the role and name, never a `ref=` inside a quoted name) on both sides before diffing. The printed `-` lines come from the baseline, `+` and context lines from the new snapshot, so the refs shown are those you can use now. *Why:* a baseline saved before a reload must show only real changes.
  - **Algorithm:** Myers O(ND) on the lines between the common prefix and suffix, so big trees with few changes are cheap; above an edit distance of 3000 (memory is O(D²)) the changed region prints as one hunk. Hunks closer than twice the context are merged. `\ No newline at end of file` follows a printed line that ends the old or the new text (twice when the last line is replaced, never for a change in the middle), as `similar` prints it.
  - **Baseline:** the last snapshot text for the same `(tabId, option set, frame)` (`lastSnapshots` in `snapshot-diff.ts`, in memory, at most 8 option sets per tab, dropped with the tab). Every `snapshot` records it (also `--delta`/`--full`, separately from the `--delta` baselines, which are unaffected); `diff snapshot` records its own snapshot as the next baseline. A `-i` or `-u` snapshot has another option set and is not a baseline for `diff snapshot` (which has neither flag). With no baseline, everything shows as added and a warning says so. `--stdin` takes a text baseline instead (`bvl snapshot > before.txt`; content-boundary marker lines in it are dropped); empty stdin is `bad_args`. `-b <file>` and extra positionals are refused with `bad_args`: the extension cannot read files and the protocol has no file inputs.
  - **Deviations from upstream 0.41.2:** (1) upstream builds its lines with a trailing newline, so when the last line of a tree changes it reports the old last line as removed and re-added (`-b +b +c`); bvl compares lines, so the counts differ in that case. (2) Without `-b`, upstream compares against empty text (observed to show the whole tree as added) and treats a nonexistent `-b` path as baseline text; bvl's "last snapshot with the same options" baseline, the warning and the `--stdin` form are bvl additions. (3) Context lines print the new side.
  - **Content boundaries:** `diff snapshot` output is page-derived and is wrapped like `snapshot`. The activity log shows the subcommand, `--selector` and `--depth`, as for `snapshot`.
- **Names and roles (`snapshot-names.ts`):** a name that is one phrase repeated twice (`"Hours Hours"`) is collapsed. Chrome's `LayoutTable*` roles are dropped and their children lifted; `InputTime`/`InputDate`/`InputDateTimeLocal`/`InputMonth`/`InputWeek`/`Date`/`DateTime` render as `group`. A nameless link or button gets a name from one page script per snapshot (only when such nodes exist, ≤ 200, main frame only, no shadow DOM): an inner img `alt`, a `role=img` aria-label, an svg `<title>`, `title` or `aria-describedby`. A nameless link without any shows `[href=<path+query+hash, or host/path cross-origin, ≤ 60 chars>, ref=eN]` (not with `-u`, which already prints `url=`).
- **Clickable non-semantic elements:** one `Runtime.evaluate` per snapshot (`clickable.ts`) finds elements without an interactive role that are `cursor:pointer` (only when the parent's cursor is not already pointer, since the cursor is inherited), have `onclick` or `tabindex >= 0`. It skips natively interactive tags, hidden and zero-size elements, and stops at 500. Each candidate is matched to its AX node by backend id (`Runtime.getProperties` + `DOM.describeNode`); the node gets a ref and the suffix `clickable [cursor:pointer, onclick]` (`focusable [tabindex]` when `tabindex` is the only reason), as in agent-browser 0.41.2 (checked on a fixture: it does **not** skip candidates inside an element that already has a ref, only inherited pointers). In `-i` mode an unnamed candidate takes its text content (whitespace collapsed, ≤150 chars) as its name; upstream keeps raw whitespace. Listeners added with `addEventListener` and elements inside iframes are not detected. Cost: every clickable wrapper adds a line with its lifted text, so a list where each row is a clickable `div` roughly quintuples `-i` size (a synthetic 150-row inbox: 8.7 KB → 41 KB); `-s` scoping keeps it down. `snapshot --json` data is `{ origin, title, refs, removedRefs, snapshot }`.
- **`read [url]`:** page text as markdown. With a URL it first runs `open <url>` (so it never navigates a shared tab), then evaluates `dist/read-extractor.js` in the page (loaded once from the extension package, so it stays out of the service-worker bundle; ~46 KB minified with Mozilla Readability and Turndown). The extractor takes the largest `main`/`[role=main]`/`article`; without one, Readability picks the content, else the body. `script`, `style`, `noscript`, `template`, `svg`, `iframe`, `nav`, `aside`, hidden and `aria-hidden` elements are dropped (`page/read-extractor.ts`). Links keep their text only, tables become GFM tables. `--outline`, `--filter` and `--max-output` run in the service worker on the markdown (`read-format.ts`) and mirror agent-browser 0.41.2: `# Outline` / `Source: <url>` / nested `- heading` list; `--filter` returns each section (heading + subsections) whose heading or own text contains the text, or `No matching page sections`; truncation appends `[truncated: showing N of M chars. Use --max-output to adjust]`. No HTTP fetch mode (`--llms`, `--require-md`) by design: the CLI stays thin and a service-worker fetch would send cookies without a visible tab.
- **Input:** `prime` checks `document.visibilityState`. If the page is hidden, a 1×1 `Page.captureScreenshot` forces a frame, and then `Input.dispatch*` delivers trusted events without focusing the tab. Held modifier keys are module-global.
- **`a11y [url] [--tags t1,t2] [-s <css>]`:** an axe-core audit (`commands/a11y.ts`, `a11y-format.ts`), read-only, mirroring agent-browser 0.41.2. With a URL it first runs `open <url>` (never navigates a shared tab). axe-core (MPL-2.0, ~650 KB) is `dist/axe.min.js`, copied unmodified from the npm package by `build.mjs` with its license in `dist/licenses/` and loaded on first use (like `read-extractor.js`), so it stays out of the service-worker bundle; `NOTICE` lists it. *Isolated world:* each frame gets `Page.createIsolatedWorld` (world name `bvl-a11y-<axe version>`) and axe is injected there with `Runtime.evaluate { contextId }`. The world shares the DOM but not page globals, so nothing is added to the page's `window`, a page's own `window.axe` is neither used nor replaced, nothing needs cleaning up, and CDP evaluation ignores the page's CSP. A page keeps the world (and axe in it) until it navigates; later audits reuse it (`typeof axe` check). *Frames:* `axe.runPartial` runs per frame, depth first, and `axe.utils.getFrameContexts` lists the child frames. Each iframe element is found with `axe.utils.shadowSelect`, its frame id with `DOM.describeNode` (`hostedFrameId`); an out-of-process iframe is reached through its child session, otherwise through the parent's session. An unreachable frame contributes `null`, which `axe.finishRun` (run in the main frame's world, where the partials are merged) skips, so iframe violations keep their frame selector path: `["#inner","#inner-img"]`. Worlds are keyed by the partials' own frame specs (`partial.frames[i].selector`, joined down the tree), which is what `finishRun` puts in node targets (not by `getFrameContexts`' `frameSelector`, a longer ancestry selector used only to find the iframe element); `getFrameContexts` runs before `runPartial`, and if its frame count differs from the partial's, those frames count as unreachable (`null`). Options are `resultTypes: ['violations','incomplete']` (keeps the payload small; `passes` and `inapplicable` are counts of rules) and, for `--tags`, `runOnly: {type: 'tag'}`. `--selector` becomes the axe context `{include: [css]}`; no match is `not_found` (`No element matches selector: <css>`). *Output:* text prints `url:`, `axe-core: <v>  violations: N  incomplete: N  passes: N`, then each rule most severe first (critical → minor, then id; `--json` keeps axe's order, as upstream) as `[impact] id: help (N nodes)`, the help URL and up to 5 targets (`  - #sel @e4`, then `… N more (use --json)`), then the `incomplete (needs manual review):` rules (axe's "could not decide", e.g. contrast over images). Targets cross an iframe with ` >> ` and shadow DOM with ` >>> `. `--json` is `{axeVersion, url, counts: {violations, incomplete, passes, inapplicable}, violations, incomplete}`; each rule has `id, impact, help, helpUrl, tags, nodeCount` and up to 10 `nodes` (`target` as axe's selector-path arrays, `html`, `failureSummary`). bvl-only: a node that is in the tab's last snapshot (`state.refs`, matched by backend node id and the OOPIF session's frame id) gets `ref` (`e4`) and `@e4` in the text; when no snapshot exists nothing is resolved. Node `html` is cut at 300 characters; a rule axe gives no impact gets the worst node's, else `unknown`. Differences from upstream: no `lifecycle` field; text sorts by impact (upstream by id) and shows at most 5 targets per rule; the audit is always of the whole tab (not of a `frame` scope). The exit code is 0 even with violations. axe measures what the tab renders: an agent tab loads in the background but is laid out, so contrast and visibility checks work; checks that depend on focus or paint can differ from a foreground tab.
- **Click actionability (`clickPoint`, `dom.ts`):** after `scrollIntoViewIfNeeded` the element must have a box, not be `visibility:hidden` or disabled, and `elementFromPoint` must hit it (or a node inside it in the flat tree, its shadow host, or its `<label>`). "Inside" follows `assignedSlot`, then `parentNode`, then a shadow root's `host`, so light-DOM content slotted into the element's shadow tree counts as the element. *Why:* a web-component button (SmartRecruiters' `<oc-button>`/`<spl-button>`) renders a `<button>` in its shadow root around a `<slot>`, and the hit is the slotted label `<span>`, which `contains` does not see; observed as a false `covered`. The center is tried first, then 10 more points spread over the box; the click goes to the first point that passes, interpolated on `DOM.getContentQuads` (so a partly covered cell or row is clicked where it is visible). If every point is covered, `prime` forces a frame and the check repeats, once at once and once after 250 ms, before failing with `covered` (`Element <element> is covered by <hit>. Dismiss it, re-snapshot, retry.`). *Why:* a hidden tab renders no frames by itself, so an overlay the page removes in `requestAnimationFrame` (Oracle's loading spinner) stays in the hit test until something forces a frame; observed as a false `covered`.
- **`wait` on hidden tabs:** `poll` forces a frame (`prime`) every 500 ms, so conditions the page only updates in `requestAnimationFrame` can become true.
- **`vitals [url]`** (`commands/vitals.ts`, maths in `vitals.ts`): read-only Core Web Vitals. A page-side script runs in an isolated world of the top frame (`Page.createIsolatedWorld`, read-only, no user gesture, not following the `frame` scope) and opens `PerformanceObserver`s with `buffered: true` for `largest-contentful-paint`, `layout-shift` and `event` (`durationThreshold: 16`), and reads `navigation` (TTFB = `responseStart`), `paint` (FCP) and `visibility-state` entries; the raw entries go back and the extension computes the numbers: CLS is the worst session window (gap < 1 s, window ≤ 5 s, shifts with `hadRecentInput` ignored, as web-vitals does), INP the longest interaction (98th-percentile estimate with ≥ 50), each with a good / needs-improvement / poor rating (web.dev thresholds). With a URL it runs `open <url>` first (so a shared tab is never navigated; guarded like `open`, and `open`'s still-loading / HTTP ≥ 400 warnings are passed through; `--json` adds `loaded` and `status`), then waits for load plus 500 ms. **Background loads:** agent tabs load hidden, and Chrome then reports no LCP (and no FCP). As web-vitals does, the first-hidden time is 0 when the first `visibility-state` entry is `hidden`, else the first later `hidden` entry; FCP/LCP that is missing, or at/after that time, is not measurable (`notMeasurable.lcp|fcp`: "page loaded in a background tab" when hidden from the start, else "page was hidden before it was reported"; before Chrome 115, without entries, only a missing metric on a hidden page). It prints `LCP: not measurable (page loaded in a background tab)`, and the value is `null`, never 0. Measure in a shared tab the user is looking at; there is no `--foreground` flag (principle 7). **INP limit:** Chrome keeps only event entries of ≥ 104 ms in the buffer, so a fast page prints `inp: -`; only interactions since page load exist at all. Text follows upstream (`url:` line, then `ttfb: … fcp: … lcp: … cls: … inp: …`, `lcp: element: <tag>`) with ratings in parentheses. `--json` `data` copies upstream's `url`, `ttfb`, `fcp`, `lcp {element,size,startTime,url}`, `cls {score,entries}`, `inp` and adds `ratings` and `notMeasurable`; **Differences from upstream 0.41.2** (checked by running it): upstream's TTFB is `responseStart - requestStart` (ours: `responseStart`, null when 0), its CLS a plain sum of shifts (ours: worst session window, ignoring shifts after input), its INP the longest event ≥ 40 ms with no interaction grouping (ours: per `interactionId`, p98 estimate), and it installs an init script so it sees interactions and shifts from navigation on (we only read what Chrome buffered). Rounding matches upstream: times to 0.1 ms (LCP and text to whole ms), CLS score to 2 decimals, shift values to 4. Not adopted: upstream's React `hydration`, `phases`, `hydratedComponents` and `lifecycle`.
- **`pdf <path> [--landscape] [--background]`:** `Page.printToPDF`, returned in `res.files`. Read-only, so allowed on agent and shared tabs. Spike result: `Page.printToPDF` works through `chrome.debugger` in headed Chrome for Testing (verified under Xvfb with `E2E_HEADFUL=1`), including on background tabs; a failure is reported as "Chrome could not print this page to PDF".
- **`set viewport <w> <h> [scale]` / `set media [dark|light] [reduced-motion]` (+ `reset`) / `set touch on|off`:** `Emulation.setDeviceMetricsOverride` / `setEmulatedMedia` / `setTouchEmulationEnabled` (5 touch points; so `'ontouchstart' in window` and `navigator.maxTouchPoints` are true after the next navigation; `setEmitTouchEventsForMouse` is deliberately not used, so `click`/`hover`/`drag`/`mouse` stay mouse input; it does not reach out-of-process iframes, which are separate targets), **agent tabs only**; a shared tab is refused with an error because the user would see their own page change. The override lives in the tab's debugger session: it persists across navigations while attached and ends on `close`, revoke or detach (the extension tracks no state). The user sees the emulated viewport if they switch to an agent tab. `set device/geo/offline/headers/credentials` are refused: they change what servers see in a logged-in account.
- **`screenshot --annotate`:** takes a fresh snapshot (new refs only for new elements, as always), reads each ref's box with `DOM.getContentQuads` and draws a red outline plus a red number tag in an `OffscreenCanvas` over the captured image (`annotate.ts`). Nothing is injected into the page. The tag number equals the ref number. Output is the save line followed by `   [N] @eN role "name"` lines; JSON adds `annotations: [{ref, number, role, name, box}]` (CSS px; viewport-relative, or page-relative with `--full`). Elements outside the viewport are skipped unless `--full`.
- **`screenshot --if-changed` / `--threshold <0-1>`:** the capture is downscaled to at most 640 px wide and compared with the last one for the same (tab, scope: viewport/full × annotated or not), kept in memory only (`capture-compare.ts`, dropped when the tab is forgotten). A pixel counts as changed if a channel differs by more than 8. The first capture is always changed (ratio 1, revision 1). Unchanged (`ratio <= threshold`) prints `✓ Screenshot unchanged (revision N, 0.0000% pixels changed)` and writes no file; the reference image is then kept so slow drift accumulates. JSON: `changed`, `pixelChangeRatio` (fraction), `revision`, `threshold`, plus `path` when changed. `--threshold` implies `--if-changed`; with `--annotate` the comparison uses the plain capture and annotations are only computed for a changed capture. The revision counts per scope. A capture on a hidden tab that never answers is retried (`captureScreenshot`).
- **`--screenshot-format png|jpeg`, `--screenshot-quality 0-100`, `--screenshot-dir <dir>`:** global flags, as in agent-browser 0.41.2 (so `bvl --screenshot-format jpeg screenshot` works; the CLI skips their values when finding the command name); only `screenshot` reads them. Format precedence: the explicit path extension (`.jpg`/`.jpeg`/`.png`), then `--screenshot-format` (`png` or `jpeg` only), then png. A flag the extension overrides gets a warning (`--screenshot-format jpeg ignored: path ends in .png`; `--screenshot-dir ignored: a path was given`). Generated names (`screenshot-<ms>.png|jpg`) go to `--screenshot-dir` (resolved against the CLI cwd) or `<tmp>/bvl/screenshots/`. JPEG quality defaults to 80 and is passed explicitly to every encoder (`Page.captureScreenshot` and `convertToBlob({type, quality: q/100})`), so all paths agree. Each image is encoded once: stitched full-page slices are captured as png and encoded at the end, and with `--annotate` the capture is a png intermediate that is drawn on and then encoded in the requested format. Unknown format, or a quality that is not an integer 0–100, is `bad_args`; a quality with a png result is ignored with a warning. The `--if-changed` history scope includes the format and quality (a different format starts a new history). The upstream `AGENT_BROWSER_SCREENSHOT_*` environment variables are not supported (the request carries no environment; forwarding it would be a protocol change).
- **`diff screenshot [-o file] [-t 0-1] [-f|--full]`** (`commands/diff.ts`, `image-diff.ts`): compares a fresh PNG capture with the last plain capture of the same (tab, scope: viewport/full), both `screenshot` and `diff screenshot` update it. No protocol change; `--baseline <file>` is rejected (`bad_args`) because the extension can't read files.
  - *Baseline store* (`capture-compare.ts`): the encoded base64 PNG, in memory only, one per (tab, scope). Dropped with the tab (`forgetCaptures`: close, revoke) and lost when the service worker restarts. Only PNG is stored: a JPEG `screenshot` (`.jpg` path or `--screenshot-format jpeg`) takes an extra PNG capture so JPEG noise never shows as changes. A capture that was truncated or is over 16 M base64 chars (~12 MB PNG) is not kept, and drops the old baseline. Decoding into pixels is refused above 16 megapixels (`--full` of a very tall page at high DPR): the error says to use the viewport.
  - *Format:* `diff screenshot` ignores `--screenshot-format`/`--screenshot-quality`: it compares lossless PNG captures and its `-o` file is a PNG diff image (upstream's documented options for `diff screenshot` don't include them either).
  - *Algorithm* (ported from agent-browser 0.41.2 `diff.rs`): a pixel differs when `sqrt(dr²+dg²+db²) > t·255·√3` (default `t` 0.1, alpha ignored); the baseline is drawn grey as `floor(floor((r+g+b)/3)·0.3)`, changed pixels `#ff0000`. Different sizes: no image, every baseline pixel counts as different, `dimensionMismatch` is set.
  - *Output copied from upstream:* exit 0 even when pixels differ; text `✗ N.NN% pixels differ` / `✓ Images match (0% difference)`, `  Diff image: <path>`, `  N different / M total pixels`; JSON `diffPath`, `differentPixels`, `totalPixels`, `mismatchPercentage` (0–100), `match`, `dimensionMismatch` (`{expected, actual}` or null). Errors: `Unexpected argument: x`, `Invalid threshold value: x`, `Threshold must be between 0 and 1, got x` (all `bad_args`).
  - *Differences from upstream:* with no earlier capture it records the baseline and returns `baselineRecorded: true` with every other field null (upstream requires `--baseline`); on a size mismatch `diffPath` is null and nothing is written (upstream echoes `-o` without writing a file); with no `-o` and a match no image is written (as upstream); an extra `  Size changed: A -> B` text line; `-s/--selector` is not supported yet.
  - *Subcommands:* `SUBCOMMANDS` in `diff.ts` maps a name to `{usage, flags, show, showFlags, run}`. The `diff` command's `log()` applies the subcommand's own redaction: only `showFlags` values and `show` positionals after the subcommand name are logged. A new subcommand must keep selectors and other free text out of `showFlags`.
- **Viewport screenshots of hidden tabs:** when `document.visibilityState` is `hidden`, the viewport is captured as a clip of the page at the visual viewport (`pageX/pageY`, `clientWidth/Height`) with `captureBeyondViewport`, the path `--full` uses, which renders the tab's own frame. *Why:* a plain capture of a background tab was reported to return another tab's picture while `--full` was right (not reproduced in headless E2E). No `prime` before it: a pending 1×1 prime capture made the next clipped capture come back blank.
- **Full-page screenshots:** the page size comes from `Page.getLayoutMetrics`. Captures in 8000 px slices are stitched in an `OffscreenCanvas`, capped at 32000 device px (`truncated` flag).

- **Attach refusals (`not_controllable`):** when `chrome.debugger.attach` fails with "Cannot access/attach", `cdp.attach` looks at the tab URL (`chrome.tabs.get`). Genuinely restricted URLs (chrome://, edge://, brave://, chrome-extension://, devtools://, the web stores…) get the "Chrome does not allow extensions to control this page (e.g. chrome:// pages)" wording. For http(s)/file/ftp pages the attach is retried 5 times, 400 ms apart (~2 s, transient overlays), then fails with an explanation that another extension has probably put its own frame into the page (password manager/autofill overlay, PDF viewer, wallet, translate), how to clear it (close the popup/overlay, disable the extension on the site, or `bvl reload`, which loses unsaved form data). Chrome's original message is always included. `onDetach` records the last detach `reason` and time per tab (`lastDetach`, cleared by a successful attach); when a re-attach is refused the error starts with "The debugger was detached (reason: X, N s ago) and Chrome refused to re-attach: …". Diagnosis without new permissions is best effort: `chrome.debugger.getTargets()` entries for the tab with a foreign `chrome-extension://<id>` URL (and an id in Chrome's message) are named in the error. Unverified: whether Chrome lists such embedded frames there at all (without the `webNavigation` permission nothing else shows them). Unit-tested only.
- **Attach conflicts:** `cdp.attach` treats "already attached" as possibly ours (a previous worker's attachment) and probes with a cheap `Runtime.evaluate`. If the probe fails, another debugger owns the tab and the command fails with "Another debugger is attached to this tab (DevTools or another extension). Close DevTools on this tab…". Chrome's wording is identical for both cases, so only the probe tells them apart. Observed in Chrome for Testing 152 (`chrome.debugger` from the extension worker): `attach` on a tab the extension already holds → `Another debugger is already attached to the tab with id: N.`; `sendCommand` or `detach` on a tab the extension does not hold → `Debugger is not attached to the tab with id: N.` (a probe on a foreign attachment fails this way). A second CDP client (such as DevTools or puppeteer) does not cause either error: Chrome allows several clients on one tab. The foreign-debugger case therefore needs another extension holding `chrome.debugger`, and is covered by a unit test, not an E2E test.
- **`batch`** (`commands/batch.ts`): `bvl batch "cmd" "cmd" …`, or one command per line with `--stdin`; `--bail` stops at the first failure; `--omit-command` (with `--json`) swaps each `command` for an `index`. The dispatcher hands the call to `runBatch`, which splits each item with a small tokenizer (single and double quotes, backslash escapes, **no expansion**) and runs it through `execute` itself, so parsing, `Ctx`, `raceDialog`, consent, errors, warnings and the activity log are exactly those of a single call. Rules:
  - **MUST** log per item through `execute` (`describe`/`logArgs` redaction) and never log the raw batch line (`batch` itself has `log: () => []` and writes no entry). *Why:* the line carries every item's free text and secrets.
  - **MUST** reject inside an item: `--session` (set it on the batch; it and `--timeout`/`--json` apply to every item, `--timeout` per item, not for the whole batch), `--stdin` (stdin is the batch), and `batch`. `eval -b` works. A rejected or malformed item (unterminated quote) is a failed item, not a failed batch.
  - **MUST** pass the guardrail flags given to `batch` (`--max-output`, `--content-boundaries`, `--allowed-domains`, `--confirm-actions`) to every item, and reject an item that repeats `--allowed-domains` or `--confirm-actions` when the batch carries it (the last value would win and could widen). Output shaping is **per item**, as in agent-browser 0.41.2 (checked: `batch` with `--max-output` and `--content-boundaries` truncates and wraps each item's text separately, each with its own nonce): the limit and markers apply to an item's stdout before items are joined, and `--json` items get `_boundary:{nonce,origin}` (bvl's addition; upstream's item has none) and truncated `result` strings (upstream does not truncate JSON). The user's popup policy applies to each item through `execute`, so an item flag can only narrow it; each confirmation card is asked per matching item.
  - **MUST** share one `AbortSignal`: when the CLI disconnects the current item aborts and the rest are skipped. A confirm/prompt dialog (item `data.dialog`) ends the batch like it ends a single command; later items would only fail with `dialog_open`.
  - Output: text is each item's non-empty stdout joined by `\n` (a failed item contributes nothing). Every stderr line of an item is labelled `✗ [n/total] <described>: …` / `⚠ [n/total] …`, where `<described>` is the activity-log redaction (`describe`), so typed text never appears (`fill #x •••`). With any failure or skipped item a summary follows on stderr: `batch: 2 of 3 steps succeeded; failed: 2 (click); skipped: 1`. Exit 1 if any item failed, with or without `--bail`. `--json` is a **top-level array** (as upstream) `[{index, command, success, result, error, code?}]`: `result` is the item's `data`, `code` the item's error code when it has one; `--omit-command` drops `command`. No summary in `--json`. `res.files` of all items are merged.
  - Not adopted from upstream: its stdin is a JSON array of argv arrays; ours is one command per line. Upstream's text output has no step labels or summary and its JSON items have no `code`; we added them because a failure could not be attributed to its step.

## Output conventions

`execute` (`dispatch.ts`) is the only place that formats results and errors.

- *Warnings:* `Result.warning` (string or list) is written to `stderr` as `⚠ <text>` lines, for text and `--json` alike; `stdout` carries only the result. Used for: a confirm/prompt dialog that opened during an action (`raceDialog`; JSON `data.dialog` also has it), a truncated full-page screenshot, the `network` "recording started" hint, the `tab` "not shared" hint, several elements matching a target (below), a `fill` the page reformatted, a page still loading after `--timeout` and an HTTP error status on navigation, and a navigation the page started that the allowed-domains policy refused (on the next command on that tab).
- *Several matches:* `resolve` (`dom.ts`) counts CSS/XPath matches (`Handle.matches`, one extra evaluation). Actions (`click`, `dblclick`, `hover`, `focus`, `fill`, `type`, `check`, `uncheck`, `select`, `scrollintoview`, `upload`) still act on the first and warn `N elements match "<t>"; used the first. Use a @ref or a more specific selector.`; `find role|text|label|placeholder|alt|title|testid` warns `N elements match <kind> "<v>"; used the first.` and points at `find nth`, `--exact`/`--name` or a @ref (for `find text` only the deepest matching visible elements count). `get`, `is`, `wait`, `scroll --selector`, `drag` and `find first|last|nth` stay silent. *Why:* agents could not tell that a selector was ambiguous.
- *`upload`:* the files are first set on a detached scratch `<input type=file>` and every 0-byte file is read in the page; a missing file (Chrome accepts any path and gives the page an empty file) fails with `bad_args` before the target is touched. An `<input type=file>` target then gets `DOM.setFileInputFiles` on its object. Any other target is clicked through the `click` path (priming, actionability) with `Page.setInterceptFileChooserDialog` enabled (always disabled in `finally`), then `Page.fileChooserOpened` (via `cdp.onEvent`, subscribed before the click) gives `backendNodeId`/`mode` for `DOM.setFileInputFiles`. Waits `min(--timeout, 5000)` ms, then `timeout` ("no file chooser opened", mentions `window.showOpenFilePicker`, which CDP cannot fulfil); `selectSingle` with several files → `bad_args`. A file chooser inside an out-of-process iframe is not supported (`bad_args`: `cdp.onEvent` only carries the tab session's events); target the `<input type=file>` there. The `upload` confirmation (`confirmCommand`) runs before `run`, so before the click. `check`/`uncheck` appends "Custom checkbox: try `click` on its label or wrapper" to a `not_visible` failure.
- *Navigation report:* `click`, `dblclick`, `tap`, `swipe`, `press`, `select` and `find … click|dblclick|select` compare the main frame's `loaderId` and URL (fragment included) before the action and after `settle`. On a change the text is `✓ Done → <url> "<title>"` (`(no title)` when empty) plus ` (refs reset: snapshot again)` when the document changed; JSON adds `navigated: {url, title}`. Not in agent-browser; added so an agent needs no `get url` after an action.
- *Empty values:* in text mode `get text|html|value|attr|title` print `(empty)` for an empty string (`get attr` of a missing attribute stays `null`); navigation results print `✓ (no title)`. JSON keeps `""`.
- *Errors:* text mode prints `✗ <message>` on stderr. `--json` prints `{ success: false, data: null, error, code? }` on stdout (exit 1); `code` is omitted when the failure has no stable code. Unknown commands also carry `type: "unknown_command"`, as agent-browser does. `UserError(message, code?)` lives in `errors.ts`.
- *Output limit:* the global `--max-output <chars>` (or the popup's default, `guardrails.maxOutput`; the flag wins) is applied in `execute` by `limitOutput` (`guardrails.ts`) to the finished `Result`. Text: `text` is cut and gets `\n[truncated: showing N of M chars. Use --max-output to adjust]` (agent-browser 0.41.2's marker). `--json`: every `data` string longer than the limit is cut the same way (`origin`, `url`, `title`, `selector` are kept) and `data.truncated` is `true`. Upstream ignores the limit in `--json`. `read` has no flag of its own.
- *Content boundaries:* `--content-boundaries` (or the popup's "always" setting; the flag can only add) wraps the printed text of page-derived commands (`snapshot`, `diff snapshot`, `read`, `a11y`, `console`, `errors`, `eval`, `get text|html|value|attr`, `dialog status` with a dialog, `network request`) when it is not empty. Format copied from agent-browser 0.41.2: `--- AGENT_BROWSER_PAGE_CONTENT nonce=<32 hex> origin=<tab URL> ---`, the text, `--- END_AGENT_BROWSER_PAGE_CONTENT nonce=<same> ---`. A fresh nonce per response. `--json` leaves `data` alone and adds `_boundary: {nonce, origin}` to the envelope. Truncation happens first, so the markers always survive. Upstream wraps only `snapshot`, `get text|html`, `eval` and `console`; wrapping `get value|attr`, `read`, `a11y`, `errors`, dialog messages and network bodies is bvl's addition. The list is `isPageContent` in `guardrails.ts`.
- *Usage:* a `bad_args` error whose message has no `Usage:` line gets `Usage: bvl <usage>` appended from the `Command` table.
- *Help:* `Command.details` (a behaviour paragraph) and `Command.examples` are rendered by `<cmd> --help`. Top-level help is split: the CLI prints the overview (what bvl is, the "Start here (for AI agents): `bvl skills get core`" line, core loop, tab consent, CLI-local commands; `cli/src/help.rs`), then the extension's `help` output: the command list by group and the global flags. See [protocol.md](protocol.md#cli-local-commands).
- *`wait`:* `--url` prints the URL that matched (`{ url }`), `--text` prints the text (`{ text }`), `wait <ms>` has `{ ms, waited: "timeout" }`; element, `--fn` and `--load` waits print `✓ Done`.
- *JSON fields:* actions echo their target (`{ clicked: "@e3" }`, `filled`, `typed`, `pressed`, `hovered`, `focused`, `checked`, `unchecked`, `scrolled`, `dragged`+`source`+`target`, `keydown`/`keyup`); `get`, `eval`, `is` and `snapshot` add `origin` (the tab URL); `get attr`/`value` use `{ value }`, `get count` `{ count, selector }`, `get box` the box fields; `console` is `{ messages: [{ type, text, args }] }` and `errors` `{ errors: [{ text, line, column, url }] }` (`args` are CDP RemoteObjects); `dialog status` has `hasDialog` and `open`; `tab` list is `{ tabs: [{ tabId, label, title, url, active, type, controlled, pending, current }] }` (`controlled` and `pending` are bvl-only).
- *Suggestions:* an unknown command gets ``Did you mean `x`?`` (JSON `suggestion`) and an unknown flag `Did you mean --x?` (`suggest` in `command.ts`: a prefix match, else edit distance ≤ 2, ≤ 1 for inputs under 4 chars).
- *Error codes (`--json` `code`):*

  | code | when |
  |---|---|
  | `unknown_command`, `bad_args` | parsing / usage |
  | `unknown_ref`, `stale_ref`, `not_found`, `not_visible`, `disabled`, `covered` | targeting (`not_found` also: unknown tab or frame, no history entry, no open dialog) |
  | `timeout` | waits, navigation with nothing committed within `--timeout`, and the user not answering a consent prompt |
  | `navigation_failed` | `Page.navigate` returned an error (DNS, network, an HTTP error with an empty body); unresolvable hosts read `Could not resolve host "<host>"` |
  | `dialog_open` | a confirm/prompt dialog blocks the tab |
  | `no_tab`, `tab_gone`, `not_shared`, `denied`, `revoked` | tabs and consent |
  | `not_controllable` | Chrome refused `debugger.attach` (restricted URL, or another extension's frame in the page); see Attach refusals |
  | `domain_blocked` | navigation refused by the user's or the agent's allowed-domains policy |
  | `not_connected`, `not_paired` | extension/proxy unreachable, CLI not paired (produced by the CLI and proxy, see [protocol.md](protocol.md)) |

  Errors that come straight from the page or Chrome (a JS exception in `eval`, a CDP failure, "Element is not editable") have no code.

## Gotchas

- Attaching shows Chrome's debugging bar. Closing it revokes the tab (see [security.md](security.md)).
- Hidden tabs throttle timers and stop `requestAnimationFrame`. Waits based on page JS may be slow in agent tabs.
- `raceDialog` returns while the command keeps running in the background. Its later side effects (grants, log entries) still happen.
- Dialogs, console messages and exceptions of an out-of-process iframe are not captured (its `Page`/`Runtime` domains are not enabled), so an `alert` inside one is not auto-accepted.
- Pointer state (`mouse`) is per tab and, like held modifier keys, lost on a service-worker restart.
- Held modifier keys (`keydown`) are shared across tabs and sessions and are lost on a service-worker restart.
- `tab` (list) assigns `tN` ids to every tab it lists, shared or not. This is intended: the agent needs an id to ask for an unshared tab.
- The supported floor is Chrome 127 (`minimum_chrome_version`). `build.mjs` targets the same version; change both together.
